## Notes

- **Signal delivery to two machines on one object.** A signal arriving through the tug's `command` port is taken by *one* of the machines the tug exhibits (probe: two `state def`s each `accept Go via cmd` — only one moves). A signal sent to the tug itself (bare `send` from a machine it exhibits) is offered to the other machine's bare `accept`. The model therefore routes ground commands and injected events through the port to the machine that owns them and the supervisor's own `SafeModeRequest`/`AbortReturn` to the tug; `GroundContact` is a separate event beside each telecommand so both the mode machine and the command-loss timer see a pass. Whether the one-consumer semantics is what the standard intends is left as a question, not a finding.
- **Backbone.** No change required. Two items the backbone could add later, modelled here without it: `integrationAndTest` and `sepCommissioning` as phases of `TethysMission::flightTimeline` (carried as `PhasePlan` rows), and an inspector recovery/retirement event (`InspectorModes.retired`).
