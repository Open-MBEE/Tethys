# Findings against OpenSysML — WP-E (modes, sequence, FDIR)

Same columns as `docs/findings.md`; ids are renumbered at integration. Probes under `model/probes/`.

| ID | Found | Version | Construct | Observed | Expected (spec §) | Status |
| --- | --- | --- | --- | --- | --- | --- |
| F-E01 | 2026-10-22 | OpenSysML v0.10.1-2054 | `assign g.missDistance := …` from a `perform action` of the part that `exhibit state g : Guard` (probe `model/probes/F-E01-exhibited-state-attribute-write.sysml`) | The assignment writes a separate materialization of `g` (`-trace`: `eval feature g -> instance#2`); the running machine keeps evaluating its own `missDistance` at the initial 20 000 km, its `accept when missDistance < 10000 [km]` never fires, and the later `Abort` is "consumed by no transition". Binding the state's attribute to the owner's (`:>> missDistance = Flight::missDistance`) behaves the same. | The exhibited state usage is one feature of the part; `g.missDistance` names the attribute of that one performance, so the write and the guard's read are the same value and the machine reaches `aborting` at t = 100 s (SysML v2 7.21.2 exhibited states as performances of the exhibiting part; KerML 7.4.9 feature chains). The model avoids the pattern: monitors read attributes the machine owns or guard on signal payloads (`TethysModes`, `TethysFdir`). | fixed in pin — OpenSysML #1387 (develop `5cd37f288`): the probe's machine processes both events (`Advanced to 200.0 (2 event(s) processed)`, `Current state: safe`, last event at 150.0) instead of leaving the `Abort` consumed by no transition |
| F-E02 | 2026-10-22 | OpenSysML v0.10.1-2054 | `accept after howLong` where `howLong` is an `in` parameter of the action definition (probe `model/probes/F-E02-accept-after-parameter.sysml`) | Instantiation fails with "accept after howLong must be constant, got sequence"; so does an owned attribute initialised from the parameter (`attribute d = howLong`) and a parameter bound to a literal (`in howLong = 20.0 [d]`). The same wait on an owned attribute with a literal value runs. | `accept after` takes any expression whose result is a `DurationValue` (SysML v2 7.16.6 Accept Action Usages: `after` is a `TriggerInvocationExpression` over a duration expression); a bound `in` parameter is such an expression. `TethysSequence::DroInsertionSequence` keeps its arc length as an owned attribute for this reason. | fixed in pin — OpenSysML #1384 (develop `5cd37f288`): `hostA` and `hostC` both run to `Action completed` with `finished = [true]`, `howLong = 20.0 [d]` |
| F-E03 | 2026-10-22 | OpenSysML v0.10.1-2054 | `send new X() via response` from a state machine whose definition owns `port response : ~CommandPort`, exhibited by a part that owns a port of the same name connected by an `interface … connect tug.response to tug.command` (both ends on the same part) | "send reaches no receiving port: port "response" is joined to no port that can receive it", whether the interface is declared inside the part or in its owner. `accept … via command` on the same state definition's `port command` does resolve to the exhibiting part's port and receives what an interface delivers there. | A state usage is an occurrence usage and may own ports; the exhibited performance's port and the part's port of the same name are bound by the exhibitor, so a `via` send should leave through the connected end as the `via` accept arrives through it (SysML v2 7.16.6 Send Action Usages, 7.21 Exhibit States). Not reduced to a standalone probe: the model instead sends the supervisor's requests to the tug itself (bare `send`), which the mode machine exhibited beside it accepts with a bare `accept` (`TethysFdir::FdirSupervisor`, `TethysModes::TugModes`). | open — OpenSysML #1388 (send via a state definition's own port through what binds or connects it) is not in the pin; the exhibiting parts now bind the mirrored port explicitly (`bind modes.command = command`, `bind fdir.command = command`), which both validators accept and which leaves every pinned modes/fdir/sequence run unchanged; no pinned run exercises the state-port `send` path until the fix is pinned |

Rows marked *fixed in pin* were re-run on OpenSysML built from source at develop `5cd37f288` (`v0.10.1-2130-g5cd37f288`), the tool pin of `scripts/fetch-tools.sh`; the rows still open reproduce on that build where `runs/` pins them.
