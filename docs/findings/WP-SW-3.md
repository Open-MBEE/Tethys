# Findings against OpenSysML — WP-SW-3 (flight software behaviour)

Same columns as `docs/findings.md`; ids are renumbered at integration. Probes under `model/probes/`;
every probe validates clean on OpenSysML `-validate -strict -warnings-as-errors` and on the pinned
pilot standalone validator (exit 0, no diagnostics), so each row is a runtime verdict, not a
grammar one. Tool: OpenSysML built from source at develop `5cd37f288`, the pin of
`scripts/fetch-tools.sh`.

Design consequences in `model/65-flight-behaviour.sysml`: sends from a state machine are written in inline exhibited state usages on the application (F-S01); machines that only receive are state definitions bound by name (F-S05); each machine of one application listens on a port of its own (F-S03); the scenarios are definitions of their own (F-S04); a port is never named like an inherited member (F-S06).
