# Findings — integration of the ten work packages

Tool boundaries that only the integrated model shows: each row is a construct that every
package passed on its own and that misbehaves once the packages share one model. Same
columns as `docs/findings.md`; probes under `model/probes/`. The model is kept as the
specification reads; nothing below is modelled around.

| F-I01 | 2026-10-22 | OpenSysML v0.10.1-2054-g0a5fa2d94 (source build at 0a5fa2d94) / pilot validator at the vendored pin | `viewpoint def Reading { frame traceability; }` with no `require constraint`, applied as `viewpoint reading : Reading;` and satisfied by a view, `view tree { … satisfy reading; }` (probe `model/probes/F-I01-viewpoint-without-constraint-satisfy.sysml`; in the model every `satisfy <viewpoint>` of `TethysViews` and `TethysViewsTooling`, 14 rows of `runs/requirements-satisfy.txt`, `runs/as-built-satisfy.txt`, `runs/wpb-budgets-satisfy.txt`) | `-satisfy` reports `? satisfy reading could not be evaluated … Error: satisfaction satisfy reading: no condition to evaluate … standing: not covered` and exits 2. Both validators accept the file. | A `ViewpointCheck` is a `RequirementCheck` (SysML v2 §9.2.17 Views library, `abstract viewpoint def ViewpointCheck :> RequirementCheck`), and a `RequirementCheck`'s verdict is the conjunction of its assumed and required constraints (§9.2.11 Requirements library: `assumptions->allTrue() implies constraints->allTrue()`); with no required constraint the conjunction over the empty set is `true` (KerML §9.2.3 `allTrue` over an empty sequence), so the viewpoint is satisfied vacuously. Expected: `✓ satisfy reading holds` — a frame with no constraint is a satisfied requirement, not an unevaluable one. | open — OpenSysML evaluation gap on constraint-less requirement checks; the viewpoints keep `frame` without `require constraint`, which is what they say |

The control without the `perform`/`bind` returns `bodyCount = 1`. Both validators accept the file. | Counting the instances of a type (KerML §8.3.4.8 `all`, SysML v2 §7.6.7) is a query over the model; it should not run the performed actions of the individuals it counts, and when it does, F-C04 applies: an action's `out` default is evaluated after its `in` parameters are bound (KerML §8.4.4.6 Function Evaluation: parameters are bound before the body is evaluated). Expected: `bodyCount = 5` (`amaranth` and the four `CaptureTargetCase` variants). | open — same defect as F-C04, reached from a new entry point; the model stays as it is and `runs/notation-readiness.txt` pins the error |
