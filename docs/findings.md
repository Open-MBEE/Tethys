| F-001 | 2026-10-21 | OpenSysML v0.10.1-2054 / pilot library at the vendored pin | `RealFunctions` | The Kernel Function Library has no natural logarithm or exponential (`RealFunctions` is arithmetic, `sqrt`, `floor`, `round`, comparisons), so the rocket equation cannot be written against the standard library alone. | KerML 9.3 Kernel Function Library gives no `ln`/`exp`; this is a standard-library gap, not a tool defect. The model carries a series `TethysEnvironment::NaturalLog` (error < 3e-5 on 0.3–3); OpenSysML's non-standard `OpenSysMLMathFunctions::ln` is not used (standard SysML only). | open — upstream library gap, candidate OMG issue |
| F-002 | 2026-10-21 | OpenSysML v0.10.1-2054 / pilot library at the vendored pin | `SampledFunctions::interpolateLinear` | Over samples (0.9647, 1462.4), (1.052, 1229.8), (1.1393, 1048.5): `interpolateLinear(fn, 1.0)` = 1135.75, `(fn, 1.1)` = 869.31, and at the sample point `(fn, 1.052)` = 997.20 (probe `model/probes/F-002-interpolate-linear.sysml`). | Linear interpolation gives 1368.35, 1101.91 and exactly 1229.8. The library text is the cause, not the evaluator: `index` is `select { … domainValues#(i) <= value }#(1)`, the *first* sample at or below `value`, not the last, so every lookup uses the first pair and extrapolates; and `Linear` computes `f = (value − lower)/(lower − upper)` (negative) then `upper.rangeValue + f·(lower.rangeValue − upper.rangeValue)`, which inverts the slope. Hand-evaluating that text reproduces 1135.75 / 869.31 exactly. SysML v2 Domain Libraries, Analysis, `SampledFunctions` (standard text; the vendored copy is the pilot's). | confirmed — upstream OMG library defect; the model uses its own `LinearInterpolation` calc and keeps the standard call in the probe |
| F-003 | 2026-10-22 | OpenSysML v0.10.1-2054 | `assign g.missDistance := …` from a `perform action` of the part that `exhibit state g : Guard` (probe `model/probes/F-003-exhibited-state-attribute-write.sysml`) | The assignment writes a separate materialization of `g` (`-trace`: `eval feature g -> instance#2`); the running machine keeps evaluating its own `missDistance` at the initial 20 000 km, its `accept when missDistance < 10000 [km]` never fires, and the later `Abort` is "consumed by no transition". Binding the state's attribute to the owner's (`:>> missDistance = Flight::missDistance`) behaves the same. | The exhibited state usage is one feature of the part; `g.missDistance` names the attribute of that one performance, so the write and the guard's read are the same value and the machine reaches `aborting` at t = 100 s (SysML v2 7.21.2 exhibited states as performances of the exhibiting part; KerML 7.4.9 feature chains). The model avoids the pattern: monitors read attributes the machine owns or guard on signal payloads (`TethysModes`, `TethysFdir`). | open |
| F-004 | 2026-10-22 | OpenSysML v0.10.1-2054 | `accept after howLong` where `howLong` is an `in` parameter of the action definition (probe `model/probes/F-004-accept-after-parameter.sysml`) | Instantiation fails with "accept after howLong must be constant, got sequence"; so does an owned attribute initialised from the parameter (`attribute d = howLong`) and a parameter bound to a literal (`in howLong = 20.0 [d]`). The same wait on an owned attribute with a literal value runs. | `accept after` takes any expression whose result is a `DurationValue` (SysML v2 7.16.6 Accept Action Usages: `after` is a `TriggerInvocationExpression` over a duration expression); a bound `in` parameter is such an expression. `TethysSequence::DroInsertionSequence` keeps its arc length as an owned attribute for this reason. | open |
