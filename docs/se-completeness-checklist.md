# What does a complete mission model contain? — systems-engineering completeness checklist

Acceptance criteria for calling the *Hesperia* model (fictional Venus orbiter + *Kestrel* descent probe, fictional *Arcturus-5H* launcher and *Meridian* ground network) **complete as a mission model**. Language/tool coverage (grammar productions, CLI/REPL/gRPC surfaces) is a separate review and is not repeated here; where a row's predicate depends on a tool surface, the surface is named and its observed behaviour quoted.

## How to read this

* **ID** — stable `SE-nnn`; never renumber, append new rows at the end of their group (gaps are reserved).
* **Lifecycle phase** — NASA phase (Pre-A, A, B, C, D, E, F) with ECSS equivalent where they differ (ECSS 0/A/B/C/D/E/F). "All" = maintained throughout.
* **Standard source** — the public document and section/table/annex the artefact is named in. NASA documents were read from the published PDFs (NASA/SP-2016-6105 Rev 2 "SEH", NPR 7123.1D, NASA-STD-7009B). ECSS standards are registration-gated and ISO/IEC/IEEE 15288 and the INCOSE SE Handbook v5 are paywalled, so for those the citation is to the document, the named DRD/product, or the ISO 15288:2023 process clause (§6.x.y), which INCOSE SEH v5 ch. 2 follows one-for-one; clause numbers inside ECSS documents are **not** cited because they were not verified against the text.
* **SysML v2 construct (spec §)** — clause numbers are those of the specification text OpenSysML pins: *OMG SysML v2.1 Beta 2 (Release 2026-07), Part 1*, rendered at `build/spec-docs/sysml.txt` by `scripts/download-spec-examples.sh` at `PILOT_RELEASE_COMMIT` in `scripts/pilot-pin.sh` (pilot tag 2026-08); KerML clauses from `build/spec-docs/kerml.txt` at the same pin. The model-library clauses (§9.2 Systems Model Library, §9.3 Metadata, §9.4 Analysis, §9.5 Cause and Effect, §9.6 Requirement Derivation, §9.7 Geometry, §9.8 Quantities and Units) are from the same document. The clause *headings* used here (7.3 Dependencies … 7.27 Metadata) match the formal/2026-03 numbering as far as the OpenSysML `docs/project/spec-compliance.md` rows use it; re-check if the model pins a different text.
* **Library** — where the vocabulary comes from. Abbreviations: **SysLib** Systems Library (`internal/workspace/libs/stdlib/Systems Library/`); domain libraries **ISQ/SI**, **Time**, **MM** ModelingMetadata, **RM** RiskMetadata, **POI** ParametersOfInterestMetadata, **RD** RequirementDerivation, **CE** CauseAndEffect, **TS** TradeStudies, **SSR** StateSpaceRepresentation, **SF** SampledFunctions, **AT** AnalysisTooling, **Geo** SpatialItems/ShapeItems; OpenSysML libraries (non-normative; `internal/workspace/libs/stdlib/OpenSysML Libraries/`) **OOSEM**, **MOSA**, **AR** AnalysisRecords, **DQ** DocumentQueries, **Sim** Simulation, **Sto** Stochastic, **SMs** StateMachines, **SSI** StateSpaceIntegration, **RF** RandomFunctions, **IdM** IdentityMetadata, **SV** SysMLValidation, **DL** DiagramLayout. A row that needs an OpenSysML library to be *expressed* (not merely executed) is marked **[ext]**: under `-strict` such a model still parses as standard SysML v2 (the libraries are ordinary SysML packages) but the pilot only validates it if the library files are loaded with it (`-migrate -portable` does this for migrated models; for Hesperia the plan is to vendor the used library files).
* **Pattern already in examples?** — where a reviewed model already shows the pattern. Abbreviations: **A11** = github.com/airbus/apollo-11-sysml-v2 (cloned at HEAD, 25 `.sysml` files, ~7 200 lines); **TR/nn** = OMG training examples `examples/sysml-v2-training/nn. …/` (downloaded by `./scripts/download-training-examples.sh`); OpenSysML `examples/` dirs by name (**oosem**, **mosa**, **rts** runtime-showcase, **robot** disposal-robot-demo, **team** disposal-team-demo, **relay** relay-probe-demo, **lander** analysis-demo, **results** analysis-results-demo, **verdicts**, **self** self-model, **import** data-import-demo, **tool** external-tool-demo, **timeline** run-timeline, **gviews** general-views-demo, **rules** self-check-rules); **WE** `docs/manual/worked-example.md`; **FL** `docs/guide/modeling-fleets.md`. "—" = none of them.
* **Priority** — must / should / could, for a *mission model* (not a toy): "must" rows are the ones a review board would reject the model for missing.
* **Checkable predicate** — phrased so it can become a `constraint def` in `Hesperia::HouseRules` (run by `-self-check-package`), a `DocumentQueries` query (run by `-run-query` / `-render-document`), a verdict command (`-satisfy`, `-requirement`, `-analysis`, `-constraint`, `-validate=<object>`), or, failing those, a script over `-convert api-json`. The prefix says which: **[R]** house-rule constraint def, **[Q]** document query, **[V]** verdict command, **[X]** script over the exported model, **[M]** manual review (no mechanical check).

### What was verified on the tool (develop @ `ac1340353`, `make build` → `bin/sysml v0.10.1-1965-gac1340353`)

Observed with probe models under a scratch directory (not committed anywhere):

1. **House rules work for intrinsic, derived reflective features.** A `constraint def` whose first `in` is typed by a metaclass (`in p : SysML::PortUsage;`) is applied to every conforming element by `-self-check-package <Pkg>` (`examples/self-check-rules/README.md`). Features observed to evaluate: `documentation`, `direction`, `shortName`, `qualifiedName`, `ownedMember`, `ownedFeature`, `ownedMetadata`, `portDefinition`, `partDefinition`, `attributeDefinition`, `requirementDefinition`, `subjectParameter`. Output: `error[self-check-rule]: Rules::portUsageDirection fails for Probe::Bus::p`, summary `Self-model check: 33 elements, 306 checks, 1 violations, 4 unevaluated`.
2. **Boundary — relationship-level and some derived features are not readable from a rule.** `ownedRelationship` (on `RequirementUsage`), `text` and `requiredConstraint` (on `RequirementDefinition`), `verifiedRequirement` (on `VerificationCaseDefinition`) and `ownedAnnotation` (on `PartDefinition`) are reported *unevaluated*, not violated: `reflective feature is not derived: SysML::Systems::VerificationCaseDefinition::verifiedRequirement` etc. `declaredShortName` and `type` are not resolvable members on those metaclasses (`error[unresolved]`, the whole run stops: "did not analyse cleanly; no check was made"); use `shortName` and the most specific redefinition (`attributeDefinition`, `partDefinition`, `portDefinition`). So predicates of the form "every X has an incoming satisfy/verify/allocate/connect" **cannot today be house rules**; they are written as **[Q]** queries instead (item 3). This is the single most important tool boundary for this checklist.
3. **Relationship predicates work as document queries.** `DocumentQueries::WhereRelated(source, relationshipKind, direction, exists)` with `relationshipKind` ∈ `specialization, subsetting, redefinition, typing, connection, allocation, satisfaction, verification, derivation, refinement` (doc comment in `DocumentQueries.sysml` l.137–139). Probe: `WhereRelated(source = WhereType(source = Descendants(source = root), type = "RequirementUsage"), relationshipKind = "verification", direction = "incoming", exists = false)` run with `-run-query "Q::Unverified root=Probe"` listed the unverified requirement usages and *not* the verified one; the same with `"connection"` over `PortUsage` listed the one unconnected port. **Gotcha:** `WhereType(... "RequirementUsage")` also returns `satisfy …` and `verify …` usages themselves (they are `SatisfyRequirementUsage`/requirement usages), so the house query must `Except` those (`WhereType(... "SatisfyRequirementUsage")`) or start from the requirement package only. The query file needs `private import KerML::Root::*;` (or `KerML::Root::Element`) for `Element`.
4. **Verdict commands**: `-satisfy` printed `✓ satisfy massReq by bus holds (on Probe::bus ID: 1)` with `standing: holds (observed: 1 run under reverse)`; `-requirement Probe::massReq` printed `✓ Requirement Probe::massReq satisfied`; `-requirement` and `-satisfy` also report the verdict of every verification case verifying the requirement (`./bin/sysml -help`).
5. `-help` lists the other surfaces predicates below rely on: `-validate[=<object>] -strict -warnings-as-errors`, `-self-check`, `-self-check-package`, `-constraint`, `-requirement`, `-satisfy[=<name>]`, `-calc`, `-analysis`, `-record-run`/`-record-into`, `-run-query`, `-instantiate`, `-action`/`-state`/`-advance`, `-schedule explore`, `-engine check|smt`, `-check-property`, `-runs`/`-seed`/`-observe`, `-sweep`/`-samples`, `-import`/`-import-map`, `-convert api-json|ttl`, `-render`/`-render-all`/`-render-document(s)`, `-format sarif|junit`, `-baseline`. REPL `%help` mirrors them (`%check-property`, `%check-witness`, `%tool`, `%engines`, …).

### Summary

* **233 rows** (SE-001 … SE-329, grouped; gaps are reserved for later additions): 133 must, 66 should, 34 could; 98 rows have **no pattern** in any reviewed model (§3 collects them).
* §2 holds the Venus-class domain list (environment constants from the NASA Venus Fact Sheet, plus derived values computed for this review), §3 what no published model covers, §4 the four verification mechanisms with snippets run on the fresh build.
* Two tool/library findings, both verified on the fresh build: (1) house rules cannot read relationship-derived features (`verifiedRequirement`, `requiredConstraint`, `ownedRelationship`, `text`, `ownedAnnotation` → "not derived"), so coverage predicates must be `DocumentQueries::WhereRelated` queries; (2) the standard SI library's `ua` (astronomical unit) evaluates to 1.496 × 10²² m (the same text is in the pilot's copy).

## 4. Verification queries — catalogue of mechanisms (all four forms were run on the fresh build)

**[R] House rule** (`-self-check-package Hesperia::HouseRules`), verified form:

```sysml
package Hesperia { package HouseRules {
    private import SequenceFunctions::*;
    constraint def requirementDefinitionHasDoc {
        doc /* SE-041: every requirement definition carries documentation. */
        in r : SysML::RequirementDefinition;
        not r.documentation->isEmpty()
    }
    constraint def requirementDefinitionHasId {
        doc /* SE-017: every requirement definition has a short-name id. */
        in r : SysML::RequirementDefinition;
        not r.shortName->isEmpty()
    }
    constraint def portUsageDirected {
        doc /* SE-102 */
        in p : SysML::PortUsage;
        not p.direction->isEmpty()
    }
    constraint def partUsageTyped {
        doc /* SE-074 */
        in p : SysML::PartUsage;
        not p.partDefinition->isEmpty()
    }
}}
```

Readable on develop @ `ac1340353`: `documentation`, `shortName`, `qualifiedName`, `direction`, `ownedMember`, `ownedFeature`, `ownedMetadata`, `portDefinition`, `partDefinition`, `attributeDefinition`, `requirementDefinition`, `subjectParameter`. Unevaluated ("reflective feature is not derived"): `ownedRelationship`, `ownedAnnotation`, `RequirementDefinition::text`, `RequirementDefinition::requiredConstraint`, `VerificationCaseDefinition::verifiedRequirement`. Unresolved (whole run refused): `declaredShortName`, `type`. **Recommendation for the gate:** run with an expected-unevaluated list (`-format json` and a script) so a rule that silently becomes unevaluated is caught; and request the missing derived features as OpenSysML fixes (each is a spec-defined derived property, so deriving it is spec-compliant).

**[Q] Relationship coverage query** (`-run-query "Hesperia::HouseQueries::Unverified root=Hesperia::Requirements"`), verified form:

```sysml
package HouseQueries {
    private import DocumentQueries::*;
    private import KerML::Root::*;
    calc def Unverified :> Query {
        doc /* SE-058: requirement usages owned by root that nothing verifies. Rows must be empty. */
        in root : Element;
        Except(source = WhereRelated(source = WhereType(source = OwnedElements(source = root), type = "RequirementUsage"),
                                     relationshipKind = "verification", direction = "incoming", exists = false),
               exclude = WhereType(source = OwnedElements(source = root), type = "SatisfyRequirementUsage"))
    }
    calc def UnconnectedPorts :> Query {
        doc /* SE-102 */
        in root : Element;
        WhereRelated(source = WhereType(source = Descendants(source = root), type = "PortUsage"),
                     relationshipKind = "connection", direction = "incoming", exists = false)
    }
}
```

Run on a probe model: with every requirement usage verified the query returns no rows; after adding one unverified usage it returns exactly `Row 1: Probe::massReq2`. Two gotchas observed: `WhereType(..., "RequirementUsage")` also matches `satisfy`/`verify` usages (they are `SatisfyRequirementUsage`s, hence the `Except`), and with `Descendants` instead of `OwnedElements` it also matches the `objective` of every verification case — so keep requirement usages in their own package and query its owned elements. The same shape with `"satisfaction"`, `"allocation"`, `"derivation"` (direction `incoming` for children without parents) and `"refinement"` covers SE-042…SE-045, SE-049, SE-061, SE-073, SE-075, SE-076, SE-109. A gate fails when a must-be-empty query has rows.

**[V] Verdicts** — `-satisfy` (every `satisfy`), `-requirement <name>` (a requirement and every verification case verifying it), `-analysis <case> [subject]`, `-constraint <name>`, `-validate=<object>` after `-instantiate`, `-engine check -action A -check-property P` (every schedule), `-runs N -seed S` (Monte Carlo), `-sweep`. Each prints a verdict line and a `standing:` line (observed / witnessed / bounded / proved); `-format junit|sarif` makes the set a CI report; `-warnings-as-errors` turns undecided values into failures.

**[X] Script over the export** — `-convert api-json` (or `ttl`) then a script, for what neither rules nor queries reach: text lint of requirement statements (SE-063), derivation cycles (SE-045), literal constants duplicated outside `Environment` (SE-301), recorded-run freshness (SE-199), id stability (SE-325).
