SCD-019 Inter-application message catalogue

Every message between the flight applications and services is a space packet on the AABP-1 software bus; its application identifier is the topic, its publisher and subscribers are the ends of the topic interface.

Message types

Message item definitions
name documentation
TelemetryMessage A bus message carrying state or housekeeping from one component to its subscribers: a space packet on the software bus that is also telemetry, so it can be routed to the ground unchanged (a TelemetryPacket on the bus).
CommandMessage A bus message that directs a component: a space packet on the software bus that is also a telecommand, so a routed ground command and an on-board request share one shape (a CommandPacket on the bus).
AttitudeStateMessage Estimated attitude quaternion, body rates and attitude-control status, published by the guidance, navigation and control application at 10 Hz for the autonomy application and the electric-propulsion control application.
NavigationStateMessage Position and velocity relative to the target or the Moon and the current ephemeris epoch, published by the guidance, navigation and control application at 1 Hz for the autonomy and inspector-handling applications.
ThrusterStatusMessage Discharge current, anode voltage, flow-controller state and accumulated impulse of each Hall thruster, published by the electric-propulsion control application at 1 Hz for the power-management and fault-protection applications.
PowerStateMessage Bus voltage, array current, battery state of charge and load-switch states, published by the power-management application at 1 Hz for the mode-management, thermal-control and fault-protection applications.
ThermalStateMessage Zone temperatures, heater duty cycles and limit flags, published by the thermal-control application every 10 s for the power-management and fault-protection applications.
LinkStatusMessage Carrier lock, received signal level, current virtual-channel rate set and frame-count, published by the telecom application at 1 Hz for the mode-management and fault-protection applications.
CaptureStateMessage Capture-mechanism arm positions, contact-force readings and the despin phase, published by the capture-control application at 10 Hz for the guidance, navigation and control and autonomy applications.
RelayStatusMessage Relay link state with Wren, store-and-forward backlog and the last inspector event, published by the inspector-handling application at 1 Hz for the autonomy and telecom applications.
FaultReportMessage A detected fault with its level and the response the fault-protection application has chosen, published on detection (no period) for the mode-management and autonomy applications.
ModeChangeMessage The commanded tug mode and the time it takes effect, published by the mode-management application on each transition for every application.
SequenceStepMessage One step of a stored sequence released by the autonomy application to the application that executes it: guidance, electric propulsion or capture control.
TimeTickMessage The one-second tick with the correlated spacecraft time, published by the time service for every component.
MessageCatalogue The catalogue of inter-application messages: one item per message type, the bus figures they must fit, and the checks that every application identifier lies in the bus topic range above the identifiers the space-link profile reserves and that no message exceeds the bus maximum.
FanoutTopic One message type from its publisher to two subscribers: a three-ended interface, which the standard permits for any interface not typed by BinaryInterface.
BroadcastTopic One message type from its publisher to three subscribers: a four-ended interface.
OnBoardBusProtocolIcd The AABP-1 protocol between the software bus controller in the board support package and each remote terminal on the on-board data bus: frame layout, addressing, the time-slot schedule within one polling period and the handling of check failures. The bus electrical and rate figures are those of TI-013.
SpaceLinkProfileIcd The MLS-2 profile of the TI-010 packet interface between the telecom application and the Meridian packet gateway: CCSDS Space Packets with a time-code secondary header, carried in fixed-length transfer frames on eight virtual channels, with a rate set per tug mode and a safe rate set that every mode falls back to. The RF carrier beneath it is TI-003.
InspectorRelaySoftwareIcd The software profile of the proximity relay between the inspector-handling application and Wren: AABP-1 frames tunnelled over the TI-004 GMSK link, the identifier block the relayed inspector packets use, the store-and-forward depth on the tug and the acknowledgement rules.
RegisterMap The register map of one remote interface unit: the address space and the data width every register respects.
ThermalPropulsionRiuRegisterMap The register map of the remote interface unit that gathers the thermistors and drives the heaters and the propellant valves.
MechanismRiuRegisterMap The register map of the remote interface unit that drives the capture mechanism, the dispenser and the docking ring and reads their position and force sensors.
RemoteInterfaceUnitRegisterIcd The register-level ICD between the remote-interface-unit driver of the board support package and each remote interface unit: the register access frame AABP-1 carries, the address and data widths, and the two register maps.
BusRemoteInterfaceUnit A remote interface unit seen from the bus: the unit of the tug structure with its remote-terminal port on the on-board data bus.
MeridianPacketGateway The Meridian ground entry point of the packet interface: where transfer frames from the stations become space packets for the operations centre and commands become frames.
WrenRelayEndpoint Wren's end of the relay profile: its software bus node behind the proximity transceiver.
